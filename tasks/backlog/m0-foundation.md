# M0 — Foundation & Toolchain

**Goal.** Turn a docs-only repository into a running application skeleton with
real enforcement behind it. Nothing user-facing ships in M0; what ships is the
machinery that makes every later milestone cheap — a strict TypeScript project,
lint rules that mechanically enforce the import matrix in
[../../docs/architecture/source-structure.md](../../docs/architecture/source-structure.md),
a test runner with coverage thresholds, a local Supabase, generated database
types, and CI jobs that do real work rather than echo success. The demo is
unglamorous and important: `npm run dev` serves the authenticated shell with all
nine sidebar items from spec §25, and every CI gate can be reproduced locally
with `npm run verify`.

The one rule that governs this milestone: **no aspirational gates.** A lint rule
without a failing fixture, a coverage threshold set to zero, or a CI job that
exits 0 unconditionally is worse than nothing, because it buys false confidence.

## Exit criteria

- [ ] `npm run verify` passes from a clean clone after only `npm install` and `supabase start`
- [ ] Every CI job runs real work — no placeholders, no unconditional `exit 0`
- [ ] The deliberate import-boundary violation fixture **fails** lint
- [ ] `npm run dev` serves the authenticated shell with all nine spec §25 sidebar items and the `+ Add Transaction` CTA
- [ ] `npm run db:types` regenerates `types/database.types.ts` and CI fails when the committed file is stale
- [ ] Importing `lib/server/supabase/admin` from a client bundle throws, and lint blocks it outside the allowlist
- [ ] Branch protection blocks a direct push to `main`

## Notes

- **M0 has no `type:contract` task.** There is no schema yet and no frontend
  work that depends on domain types. The contract-first protocol starts at
  [M1-B04](m1-auth-and-profile.md).
- **M0-B02 and M0-B07 are the two tasks that make later milestones honest.**
  Import boundaries stop `lib/core` from acquiring a dependency on Next, and
  stale-types detection stops a migration from landing without its generated
  types. Both fail loudly by design.
- Sequencing inside M0: B01 → B03 → {B02, B04, B05} → {B06, B07, F01} → F02,
  with the devops tasks B08–B12 starting as soon as B03 lands a script surface
  to call.
