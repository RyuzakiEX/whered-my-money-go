# M3 — Transactions & Categories

**Goal.** The core data-entry loop. Everything downstream — the dashboard,
budgets, Safe to Spend, the timeline — is a view over transactions, so this
milestone decides the shape of the app's most important table. Three pieces of
design work matter here: **amounts are positive with direction carried by an
enum** (spec §22 says `amount`; the physical column is `amount_minor bigint` and
always positive), **transfers are two paired legs** so moving money between your
own accounts is never mistaken for spending, and **RLS must check cross-table
ownership** — the subtle case where a naive policy lets a user attach their
transaction to someone else's account. The demo makes spec §31 Q2, Q3, and Q4
answerable: add income, add an expense, categorise, search, edit, delete.

## Exit criteria

- [ ] A user can add income, add an expense, edit, and delete transactions
- [ ] Default categories from spec §7 are seeded on signup, idempotently
- [ ] Transfers create two balance-neutral legs, deleted together
- [ ] Search, filter, and sort work, and the filter state lives in the URL
- [ ] Account balances update correctly and immediately after any transaction change
- [ ] **pgTAP proves a user cannot attach a transaction to another user's account or category**
- [ ] A category's type must match the transaction type it is used on
- [ ] Spec §31 Q2, Q3, Q4 are answerable in the UI
- [ ] Future-dated transactions are excluded from spending totals and from balances

## Demo script

Run on a preview deployment:

1. Sign in. Open `+ Add Transaction` from the dashboard.
2. Add income: Salary, ₱35,000, today, to the Bank account.
3. Add an expense: Food, ₱1,250, today, from Cash.
4. Show the transactions list — both rows, grouped by date, signed and coloured.
5. Filter to Food. Show the URL changed; reload; the filter persists.
6. Edit the expense to ₱1,500. Show the Accounts page balance updated.
7. Delete it, then undo from the toast.
8. Add a transfer of ₱5,000 from Bank to Cash. Show both balances moved and
   the total unchanged.
9. Open Settings → Categories. Show the 16 seeded defaults and that a default
   cannot be deleted.

## Notes

- **This milestone unblocks M4, M5, M6, and M8.** Its schema shape is
  load-bearing for all of them, so [M3-B03](#tasks) and [M3-B05](#tasks) deserve
  more review attention than their size suggests.
- [M3-B04](#tasks) is the security-critical task. The cross-table ownership case
  is the one a plausible-looking policy gets wrong —
  [rls-policies.md](../../docs/architecture/rls-policies.md#cross-table-ownership).
- Future-dated transactions are introduced here but only *used* in
  [M7](m7-safe-to-spend.md) and [M8](m8-money-timeline.md). The rule that they
  are excluded from every actuals aggregate has a wide blast radius — it is
  repeated in the M4 aggregate tasks deliberately.
