# Source Structure

> [!IMPORTANT]
> **PLANNED — not yet created.** No application code exists in this repository
> yet. This document is the target structure that [M0](../../tasks/backlog/m0-foundation.md)
> creates and every later milestone builds inside. It is written first because
> the stream split, the lint rules, and `CODEOWNERS` all derive from it.

This is the load-bearing architecture document. It answers three questions:

1. **Where does a given piece of code go?**
2. **What is that code allowed to import?**
3. **Which stream owns it** — so frontend and backend can work the same
   milestone in parallel without colliding?

Related: [system-architecture.md](system-architecture.md) for the runtime
topology, [ADR-0001](../adr/0001-single-nextjs-app-not-monorepo.md) for why this
is one app rather than a monorepo, and
[ADR-0003](../adr/0003-pure-typescript-domain-core.md) for why `lib/core` is
dependency-free.

## Import rules

This matrix is the point of the document. It is enforced mechanically by
ESLint `no-restricted-imports` ([M0-B02](../../tasks/backlog/m0-foundation.md)),
with a deliberate violation fixture that **must** fail lint — otherwise the
rules are aspirational, and aspirational rules rot.

| Layer | May import | Must never import |
|---|---|---|
| `lib/core` | `lib/core`, TypeScript stdlib | React, Next, `supabase-js`, Zod, date libraries, `process.env`, anything doing I/O |
| `lib/server` | `lib/core`, `lib/validation`, `lib/utils`, `supabase-js`, Next server APIs | `components/*`, browser APIs, `next/navigation` client hooks |
| `lib/validation` | Zod, `lib/core` types | `lib/server`, `components/*` |
| `lib/utils` | TypeScript stdlib, `Intl` | `lib/server`, `lib/core` internals, React |
| `app/(app)`, `app/(auth)` | `lib/server`, `lib/core`, `lib/validation`, `components` | `lib/server/supabase/admin` |
| `components/*` | `lib/core` **types**, `lib/utils`, `lib/validation` | `lib/server` (anything), `supabase-js` |
| `components/charts` | the charting library | `lib/server` |
| Everything except `components/charts` | — | the charting library directly |

### Why `lib/core` is quarantined

The Safe to Spend and forecasting math is the product. It has to be trivially
testable — thousands of cases, no database, no clock, no network — and it has to
be reusable unchanged by V2's What-If feature, which re-runs the same functions
with perturbed inputs.

Three specific bans deserve their reasons:

- **No `process.env`** — a pure function's output must depend only on its
  arguments. Configuration is injected by the caller.
- **No `Date.now()` or `new Date()`** — `today` is always a parameter. A test
  that depends on the wall clock fails on the 31st of the month, and
  month-boundary bugs are exactly what this code must get right.
- **No date library** — recurrence math operates on calendar dates in the
  user's timezone, never on UTC instants. Bringing in a library invites
  someone to reach for an instant-based API. See
  [../domain/recurrence.md](../domain/recurrence.md).

### The `admin.ts` restriction

`lib/server/supabase/admin.ts` constructs a client with the `service_role` key,
which bypasses **all** Row Level Security. It is the single most dangerous file
in the repository.

Three independent controls, because one is not enough:

1. **Lint** — `no-restricted-imports` permits importing it only from an explicit
   path allowlist (migrations tooling, seed scripts, and later, scheduled jobs).
2. **Runtime** — the module throws on import if it detects a browser bundle.
3. **Review** — `CODEOWNERS` flags any change to it.

The MVP has **no** legitimate use for it in request handling. If a feature seems
to need it, that is a signal the RLS policy is wrong, not that the guard should
be relaxed. See [../security/security-model.md](../security/security-model.md).

## Stream ownership

This is what makes `stream:frontend` and `stream:backend` work the same
milestone simultaneously without merge conflicts — ownership is by directory,
so the two streams touch disjoint files.

| Path | Stream |
|---|---|
| `app/**` (pages, layouts, route handlers) | `stream:frontend` |
| `components/**` | `stream:frontend` |
| `lib/core/**` | `stream:backend` |
| `lib/server/**` | `stream:backend` |
| `supabase/**` | `stream:backend` |
| `types/database.types.ts` | `stream:backend` (generated) |
| `lib/validation/**` | `stream:shared` — backend authors, frontend consumes |
| `lib/utils/**` | `stream:shared` |
| `tests/unit/**`, `tests/integration/**` | `stream:backend` |
| `tests/e2e/**` | `stream:devops` |
| `.github/**`, config files | `stream:devops` |
| `docs/**`, `workflow/**`, `tasks/**` | whoever changes the behaviour being documented |

### The contract-first protocol

`lib/validation` and `lib/core/types.ts` are the handoff. Every milestone starts
with one small `type:contract` task on the backend stream that lands:

1. the migration,
2. the regenerated `types/database.types.ts`,
3. the Zod schemas in `lib/validation`,
4. the domain types in `lib/core/types.ts`.

That task **blocks** the milestone's frontend tasks. Once it merges, frontend
builds against real types with fixture data while backend implements the queries
and actions in parallel. Neither waits on the other, and the types are the
single source of agreement.

Full protocol: [workflow/05-milestones-and-streams.md](../../workflow/05-milestones-and-streams.md).

## Conventions

- **Route groups** `(marketing)`, `(auth)`, `(app)` carry different layouts and
  different auth requirements. The parentheses keep them out of the URL.
- **Server Components by default.** `'use client'` is an exception that needs a
  reason: interactivity, browser API, or a chart. See
  [frontend-architecture.md](frontend-architecture.md).
- **One file per aggregate** in `queries/` and `actions/` — `accounts.ts`,
  `transactions.ts`, `budgets.ts`, `goals.ts`. Not one file per operation.
- **Mappers are mandatory.** Database rows never leak into `lib/core` or into
  components. `types/database.types.ts` is generated and shaped by Postgres;
  domain types are shaped by the product. Keeping them separate is what lets a
  column rename stay a backend-only change.
- **Money never crosses a boundary as a float.** Minor units end-to-end;
  parsing happens at the input edge, formatting at the output edge. See
  [../domain/money-and-rounding.md](../domain/money-and-rounding.md).
- **Cache tags are constants**, defined in `lib/server/cache/`, never inline
  string literals. See [state-and-caching.md](state-and-caching.md).

## What is deliberately absent

- **No `src/` directory.** Flat top-level `app/`, `lib/`, `components/`. One
  fewer path segment in every import.
- **No `pages/`.** App Router only.
- **No ORM.** `supabase-js` plus generated types. See
  [ADR-0002](../adr/0002-supabase-cli-migrations-as-schema-source-of-truth.md).
- **No `services/` or `repositories/` layer.** `queries/` and `actions/` are that
  layer; a third name for the same idea would only invite inconsistency.
- **No global client state store.** Server Components hold the data; URL search
  params hold view state. Reach for a store only when something genuinely
  client-owned and cross-component appears — and record an ADR when it does.
